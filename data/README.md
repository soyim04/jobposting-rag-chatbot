# 데이터 카드: 점핏 개발 직군 채용공고

챗봇이 답변 근거로 사용하는 채용공고 데이터셋의 설명서입니다.
아래 개요~제외 기준의 수치는 **평가용 9/30 스냅샷**(사용 문서 101건) 기준입니다. 최신 서비스용 데이터는 [평가용·서비스용 데이터 분리](#평가용서비스용-데이터-분리)를 보세요.

## 평가용·서비스용 데이터 분리

재수집하면 `postings.csv`가 덮어써지므로, 평가 정답이 흔들리지 않게 9/30 수집본을 따로 보존하고 용도를 나눕니다.

| 용도 | 공고 목록 | 원문 | 청크 | 사용 문서 |
|---|---|---|---|---|
| 평가 (고정) | `eval_snapshot_2026-09-30/postings.csv` | `raw/2026-09-30/` | `chunks/eval/` | 101건 |
| 서비스 (최신) | `postings.csv` | 각 행의 `raw_path` (수집일별 폴더) | `chunks/service/` | 125건 (10/02 기준, 진행 중 111건) |

- 스냅샷은 10/02 재수집 직전의 `postings.csv`를 그대로 복사한 것입니다 (193행). 이후 수정하지 않습니다.
- 수집 스크립트는 원문을 그날 날짜 폴더에만 쓰므로 `raw/2026-09-30/`은 재수집해도 바뀌지 않습니다.
  스냅샷 보존 시 사용 문서 101건의 원문이 모두 있고, 원문으로 다시 계산한 `content_hash`가 스냅샷 값과 모두 일치함을 확인했습니다.
- 청킹: `chunk_postings.py`(기본값 `eval`)는 스냅샷을, `chunk_postings.py service`는 최신 `postings.csv`를 씁니다.
  분리 전후로 평가용 청크 파일이 바이트 단위로 같음을 확인했습니다 (전략 A 584개, B 628개).
- 수집(`collect_jumpit.py`)과 마감 판정(`posting_status.py`)은 최신 `postings.csv`, 즉 서비스용만 다룹니다.

## 제외 기준

**수집 범위 (원문을 받기 전에 거름)**

| 사유 | 기준 | 건수 |
|---|---|---|
| 경력 범위 밖 | 최소 경력이 4년 이상 | 89 |

**품질 기준 (수집한 뒤에 거름)**

| 사유 | 기준 | 건수 |
|---|---|---|
| 필수 항목 미기재 | 주요업무 또는 자격요건이 비어 있음 | 3 |
| 본문 100자 미만 | 6개 항목 합계가 100자 미만 | 3 |

한 공고가 여러 사유에 해당하면 모두 기록합니다. 품질 기준의 두 사유는 같은 3건이 동시에 해당하므로, 품질 기준으로 제외한 문서는 3건입니다.

이 3건은 리베코이앤씨의 공고 3개(54941019, 54940975, 54941009)로, 본문이 27~35자입니다. 주요업무 한 줄 외에 자격요건·우대사항·복지가 모두 비어 있고, 기술스택 태그가 "Indicative"뿐입니다. 업무도 CATIA·ABAQUS·LabVIEW를 쓰는 기계·설계 직무로, 개발 직군으로 분류된 것 자체가 오류로 보입니다.

### 기준 변경 기록

| 변경 | 이유 | 결과 |
|---|---|---|
| 본문 기준 300자 → 100자 | 내용이 정상인 짧은 공고 9건까지 걸러짐 | 사용 문서 92건 → 100건 |
| 사유 문구 "본문 부족 (이미지 공고 가능성)" → 확인된 상태로 기록 | 리베코이앤씨 공고를 직접 확인해 보니 이미지 공고가 아니라 내용 미기재 | 사유: 필수 항목 미기재 |
| 첫 번째로 걸린 사유만 기록 → 해당 사유 모두 기록 | 본문 100자 미만에도 해당하는데 0건으로 집계됨 | 본문 100자 미만 0건 → 3건 |

| 파일 | 내용 | 저장소 공개 |

| `collection_summary.csv` | 수집을 실행할 때마다 한 줄씩 쌓이는 요약 | 공개 |
| `raw/{수집일}/{공고ID}.json` | 공고 원문 스냅샷 | 비공개 (`.gitignore`) |
| `raw/eval_snapshot_2026-09-29/` | 평가셋 초안(34문항) 작성에 사용한 공고 12건의 원문 | 비공개 (`.gitignore`) |

`collection_summary.csv`의 9/30 기록 4줄은 위의 기준 변경 과정에서 실행한 기록입니다. 첫 수집, 재실행 확인, 사유 문구 수정, 복수 사유 기록 순이며, 앞의 줄에는 당시 사유 문구가 그대로 남아 있습니다.

### `postings.csv` 컬럼

| 컬럼 | 설명 |
|---|---|
| `posting_id` | 점핏 공고ID (URL `/position/{공고ID}`의 숫자) |
| `source` | 출처 (`jumpit`) |
| `company`, `title` | 기업명, 공고 제목 |
| `job_categories` | 점핏 직무 분류 (쉼표로 여러 개) |
| `career_min`, `career_max` | 점핏에 등록된 최소·최대 경력(년) |
| `newcomer` | 점핏의 신입 공고 여부 (Y/N) |
| `education`, `location` | 학력 조건, 근무지 |
| `tech_stacks` | 기술스택 태그 |
| `published_at`, `closed_at` | 게시일, 마감일 (`상시`는 상시채용) |
| `status` | `진행 중` / `마감` (마감일 지남) / `조기 마감` (마감일 전에 목록에서 사라짐) |
| `first_collected`, `last_seen` | 처음 수집한 날, 마지막으로 목록에서 확인한 날 |
| `content_hash` | 본문 비교용 해시. 재수집 때 값이 바뀌면 새 스냅샷을 저장 |
| `char_count` | 본문 6개 항목 글자 수 합계 |
| `included`, `exclude_reason` | 사용 여부(Y/N)와 제외 사유 (여러 개면 `; `로 구분) |
| `raw_path` | 최신 원문 스냅샷 경로 |
| `url` | 점핏 공고 페이지 |

경력 범위 밖으로 제외한 공고는 상세 내용을 조회하지 않아 학력·근무지·기술스택·글자 수가 비어 있습니다.

## 갱신 방법

```bash
python src/collect_jumpit.py
```

- 새 공고는 추가하고, 본문이 바뀐 공고는 그날 날짜 폴더에 새 스냅샷을 저장합니다.
- 목록에서 사라진 공고는 삭제하지 않고 `status`만 `마감` 또는 `조기 마감`으로 바꿉니다.
- 이미 수집한 공고는 본문이 같으면 "변경 없음"으로 처리되어 중복이 생기지 않습니다.
- 요청마다 0.7초씩 쉬어 서버 부하를 줄입니다.

| 재수집 처리 | 확인 여부 |
|---|---|
| 중복 없이 "변경 없음" 처리 | 확인 (9/30 재실행, 103건) |
| 새 공고 추가 | 확인 (9/30 재실행, 55097733 1건) |
| 본문 변경 시 새 스냅샷 저장 | 아직 발생하지 않음 |
| 사라진 공고의 마감 처리 | 확인 (10/02 재실행, 마감 15건 · 조기 마감 4건) |

## 알려진 이슈

- **메타데이터와 본문 불일치**: 점핏 분류와 공고 본문이 다른 사례가 있습니다. 필터는 점핏 분류를 쓰되, 답변에는 본문 조건을 함께 표시할 예정입니다 (제안서 6-3).
  - 지피에이코리아(55113981): 경력 1~3년으로 등록, 본문 자격요건은 경력 5년 이상
  - 코즈코리아(55055492): 신입 공고로 등록, 본문은 "경력 3~7년차 수준 예상"
  - 쿤텍(55060963): 서버/백엔드·Python으로 등록, 본문은 임베디드 C/C++
  - 휴먼에스(55037758): 제목은 PHP 서버개발자, 직무 분류는 기술지원·정보보안·프론트엔드
- **같은 제목의 재게시 공고**: 쿤텍처럼 같은 제목으로 공고를 다시 올리는 기업이 있어, 공고는 항상 공고ID로 구분합니다.

## 이용 조건

- robots.txt상 공고 목록·상세 페이지는 수집 제한 경로가 아닙니다 (2026-09-29 확인).
- 점핏에 적용되는 사람인 회원약관 제19조에 따라 비상업 학습 목적으로만 사용하며, 공고 원문은 저장소에 공개하지 않습니다.
