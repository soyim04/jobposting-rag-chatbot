# 메타데이터 설계 (3단계: 파싱·정제·청킹)

청크에 붙이는 메타데이터를 **어디에 쓰는지**(검색 필터 / 답변 출처 표시 / 내부 관리) 기준으로 정리한 문서입니다.
수치는 평가용 9/30 스냅샷(`data/chunks/eval/strategy_a.jsonl`, 공고 101건, 청크 685개 = 본문 584 + 공고 개요 101) 기준입니다.

## 설계 원칙

1. **공고 단위 조건은 공고 표에서, 청크 단위 조건은 벡터 DB에서 거른다.**
   경력·직무·기술스택·마감 여부는 공고 하나에 하나씩 붙는 값이므로 `postings.csv`(평가는 스냅샷)에서 먼저 공고ID를 고르고,
   벡터 검색은 `posting_id`가 그 목록에 드는 청크로만 제한한다. 항목(자격요건/우대사항 등) 같은 청크 단위 조건만 벡터 DB 필터로 쓴다.
   → 리스트 값(직무, 기술스택)을 벡터 DB에 넣는 방식에 의존하지 않아도 된다.
2. **시간에 따라 바뀌는 값은 저장하지 않고 질문 시점에 계산한다.** 마감 여부가 대표적이다 (`status` 항목 참고).
3. **청크 파일(jsonl)은 의미에 맞는 타입으로, 벡터 DB 저장 형식 변환은 색인 단계에서 한다.**
   청크 파일은 벡터 DB를 바꿔도(6단계 실험) 그대로 쓰여야 하기 때문이다.

## 필드 목록

### 검색 필터용

| 필드 | 타입 | 값 분포 (9/30, 공고 101건) | 쓰는 곳 | 비고 |
|---|---|---|---|---|
| `career_min` | 정수 | 0: 14 · 1: 22 · 2: 17 · 3: 48 | "N년차 지원 가능" 필터: `career_min ≤ N ≤ career_max` | 문자열이면 `"10" < "3"`으로 비교되어 정수로 저장 |
| `career_max` | 정수 | 0~20 (0: 14, 10: 26, 20: 17 …) | 위와 같음 | 0은 신입 전용. 20 등 큰 값이 "상한 없음"의 의미인지는 점핏에서 확인되지 않아 등록값 그대로 쓴다 |
| `newcomer` | 참/거짓 | Y: 14 · N: 87 | "신입 가능" 필터 | 9/30 데이터에서 `newcomer=Y` ⇔ `career_min=0` 14건이 정확히 일치. `postings.csv`의 `"Y"/"N"`을 참/거짓으로 저장 |
| `job_categories` | 문자열 목록 | 16종 (서버/백엔드 72, 프론트엔드 30, devops 18, 웹 풀스택 17 …) | 직무 필터 (공고 표에서) | 한 공고가 여러 직무에 속함. 수집 범위 3개 직무 외 분류도 함께 붙어 있음 |
| `tech_stacks` | 문자열 목록 | 165종, 공고당 1~10개, 빈 공고 0건 | 기술스택 필터 (공고 표에서) | 대소문자 표기만 정리 (`TECH_STACK_FIXES`). 정리 후 대소문자·공백만 다른 중복 0건. 동의어 병합(JS↔JavaScript 등)은 하지 않음 |
| `education` | 문자열 | 빈 값 0건 (대학교졸업(4년) 이상, 무관, 고등학교졸업 이상 등) | 학력 조건 필터 (공고 표에서), 답변 표시 | 4단계에서 추가. 점핏 등록값 그대로 |
| `location` | 문자열 | 빈 값 0건 | 근무지 필터 (공고 표에서, 시·구 단위 포함 여부), 답변 표시 | 4단계에서 추가. 주소 원문 그대로 |
| `closed_at` | 날짜 문자열 `YYYY-MM-DD` | 2026-09-30 ~ 2026-10-29, `상시` 0건 | 마감 여부 계산, "이번 주 마감" 같은 기간 필터 | `상시`는 마감 없음으로 취급 (현재 데이터엔 없음) |
| `section_key` | 문자열 | 7종 (본문 6개 항목 + `overview`) | "자격요건만 검색" 같은 항목 필터 (벡터 DB에서) | 질문 의도별 항목 매핑은 4단계 평가 결과를 보고 결정 |
| `posting_id` | 문자열 | 101종 | 공고 표에서 고른 공고로 검색 범위 제한 | 같은 제목 재게시가 있어 공고는 항상 이 값으로 구분 |

### 답변 출처 표시용

| 필드 | 예시 | 쓰는 곳 |
|---|---|---|
| `company`, `title` | 인공지능팩토리 / Builder / Forward Deployed Engineer (FDE) 채용 | 답변의 근거 공고 표기 |
| `section` | 자격요건 | "어느 항목에 쓰여 있었는지" 표기 |
| `source_url` | `https://jumpit.saramin.co.kr/position/54895343` | 원문 링크 (원문 대신 링크로 안내, 재배포 금지 조건) |
| `closed_at` + 계산한 마감 여부 | 2026-09-30 · 마감 | 지표 1순위(최신성): 마감된 공고는 답변에 마감 표시 |
| `collected_at` | 2026-09-30 | "언제 기준 정보인지" 표기 |

본문 앞 머리말(`[회사/제목/항목]`)에도 회사·제목·항목이 들어가 있어 임베딩에 반영된다.

### 공고 개요 청크 (4단계에서 추가)

학력·근무지는 `postings.csv`에만 있고 공고 본문 6개 항목에는 대부분 없어서, "4년제 안 나와도 되는 곳" 같은 질문을 검색으로 찾을 수 없었다
(평가셋 A11 검수 중 발견). 그래서 공고마다 공고 정보를 본문으로 만든 청크를 하나씩 추가한다.

- 항목키 `overview`, 항목 이름 "공고 개요". 전략 A·B 모두 같은 청크 1개.
- 내용: 회사, 공고명, 직무, 경력(신입 또는 N~M년), 학력, 근무지, 마감일, 기술스택.
- **마감일(날짜)은 넣고 마감 상태는 넣지 않는다.** 날짜는 바뀌지 않는 사실이지만, 상태는 기준일에 따라 바뀐다.
  답변 단계에서 LLM에 기준일을 함께 주고 상태는 `effective_status`로 계산한 값을 쓴다.
- 확인할 점: 길이·형식이 비슷해 서로 비슷하게 임베딩될 수 있다. 4단계 첫 실행에서 개요 청크가 top-k를 얼마나 차지하는지 본다.

### 내부 관리용

| 필드 | 쓰는 곳 |
|---|---|
| `chunk_id` | `{공고ID}_{항목키}_{조각번호}_{전략}`. 벡터 DB 문서 ID, 평가 시 검색 정답 비교 |
| `strategy` | 청킹 전략 A/B 구분. 전략별로 벡터 DB 컬렉션을 따로 만들 예정 |
| `chunk_index_in_section`, `chunk_total_in_section` | 전략 B에서 나뉜 조각 위치. 앞뒤 조각을 함께 보여 줄지 판단 |
| `char_count` | 청크 통계표, 너무 짧은/긴 청크 점검 |

### 저장은 하지만 검색·답변에 쓰지 않는 필드

| 필드 | 이유 |
|---|---|
| `status` | **수집 시점** 상태라 시간이 지나면 틀린다 (10/02 기준 9/30 사용 문서 중 12건이 마감일이 지났는데 `진행 중`으로 남아 있었음). 수집 기록으로만 남기고, 마감 여부는 `src/posting_status.py`의 `effective_status(closed_at, status, 기준일)`로 계산한다. 벡터 DB에는 넣지 않는다. |

마감 여부 계산의 기준일: 서비스는 오늘 날짜. 평가는 정답이 흔들리지 않도록 **2026-10-02**로 고정한다 (`eval/README.md`).

## 벡터 DB 저장 형식 (색인 단계에서 변환)

ChromaDB 1.5.9로 실제 동작을 확인했다 (2026-10-02, `src/build_index.py`).

| 확인할 점 | 결과 | 대응 |
|---|---|---|
| 메타데이터 값으로 리스트를 받는지 | 받음 (1.5.9) | 그래도 설계 원칙 3(벡터 DB를 바꿔도 같은 형식)에 따라 쉼표로 이은 문자열로 저장. 필터는 설계 원칙 1대로 공고 표에서 |
| 크기 비교(`$gt`, `$lt`)가 날짜 문자열에 되는지 | **안 됨** (정수·실수만 허용) | `closed_at_int`(예: `20261014`, `상시`는 `99991231`)를 함께 저장 |
| `$in`으로 공고ID 목록 필터가 되는지 | 됨 (검색 `query`와 함께 써도 동작) | 설계 원칙 1 그대로 사용 |

`status`는 벡터 DB에 넣지 않는다. 컬렉션은 전략별로 `eval-a-text-embedding-3-small`, `eval-b-text-embedding-3-small` (`chroma_db/`, 커밋하지 않음).

## 알려진 한계

- **점핏 등록값과 본문이 다른 공고**가 있다 (`data/README.md` > 알려진 이슈: 지피에이코리아는 경력 1~3년으로 등록, 본문은 5년 이상).
  필터는 등록값으로 걸고, 답변에는 본문 조건을 함께 보여 준다. 실제로 오답을 만드는지는 5단계 오답노트에서 확인한다.
- **수집 범위 밖 직무 분류가 함께 붙어 있다** (기술지원, HW/임베디드 등). 백엔드·프론트엔드·풀스택 중 하나를 포함한 공고만 수집했으므로,
  직무 필터는 "포함 여부"로 건다 (예: 서버/백엔드를 포함한 공고 72건).
- **기술스택 동의어**는 병합하지 않았다. "JS 쓰는 공고" 같은 질문에서 검색이 빠지는지 4~5단계에서 확인한다.
