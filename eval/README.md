# 평가셋 (4단계)

`eval_set.csv`는 평가용 9/30 스냅샷(`data/eval_snapshot_2026-09-30/`, 사용 문서 101건) 기준으로 다시 만든 평가셋입니다.
`eval_set.xlsx`는 1단계 초안(9/29 공고 12건 기준, 34문항)으로, 이력 확인용으로만 남겨 둡니다.

|---|---|---|---|
| 정답형 | 20 | A01~A20 | 사실 확인 4 · 공고 선택 6 · 조건으로 찾기 5 · 비교·종합 3 · 최신성 2 |

| 함정 | 5 | T01~T05 | 표기 차이 · 분류-본문 불일치 · 다른 공고 섞임 · 마감 공고 · 부정 조건 |

## 열 설명

| 열 | 내용 |
|---|---|
| `검색 범위` | `전체` / `공고 선택: 공고ID`(사용자가 공고를 고른 상태) / `필터: 조건`(위 필터 정의) |
| `정답` | 사람이 읽는 모범 답안 |
| `필수 요소` | 답변 정확도 채점 기준. `;`로 구분 |
| `근거` | 정답 근거 위치. `공고ID/항목키` 형식, `;`로 구분. 항목키는 `serviceInfo`·`responsibility`·`qualifications`·`preferredRequirements`·`welfares`·`recruitProcess`, 그리고 학력·근무지·마감일 같은 공고 정보가 든 `overview`(공고 개요) |
| `섞이면 안 되는 내용` | 답변에 들어가면 오답 처리하는 공고·내용 |
| `초안 문항` | 초안(`eval_set.xlsx`)의 문항 ID. 새로 만든 문항은 `신규` |

근거를 청크ID가 아니라 `공고ID/항목키`로 적는 이유: 청크ID는 전략(A/B)과 분할 번호에 따라 달라지지만 공고·항목은 같아서,
전략 A·B를 같은 정답으로 비교할 수 있다.

## 채점 기준

| 지표 | 계산 | 대상 |
|---|---|---|
| 검색 적중률 | top-k 검색 결과에 `근거`의 `공고ID/항목키`가 하나라도 있으면 적중. 함께 **근거 재현율**(근거 중 찾은 비율)도 기록 | 정답형·함정 25문항 (문서에 없음 5문항은 근거가 없어 제외) |
| 답변 정확도 | 정답(1) / 부분(0.5) / 오답(0). 필수 요소를 모두 말하면 정답, 일부만 말하면 부분, `섞이면 안 되는 내용`이 들어가면 필수 요소와 관계없이 오답 | 정답형·함정 25문항 |
| 근거 표시 정확도 | 답변에 표시한 출처 공고가 `근거`의 공고와 일치하는지. 틀린 공고를 표시하면 오답, 일부 누락이면 부분. 정답 문장에 회사명이 나오는 공고(A12 코즈코리아 등)는 함께 표시해도 허용 | 정답형·함정 25문항 |
| 출처 정확도 | 답변이 인용한 원문 문장이 LLM에 넘긴 근거(청크 본문 + 마감일·상태 줄)에 글자 그대로 있는 비율 (코드로 대조, 공백 차이는 무시). 제안서 9-3 지표 2순위 | 인용이 있는 모든 문항 |
| 문서에 없는 질문 처리 | "확인되지 않습니다"처럼 모른다고 답하고 다른 공고 내용으로 지어내지 않으면 정답 | 문서에 없음 5문항 |

### 판정 규칙

- **질문 밖 정보**: `정답`과 `필수 요소`는 질문에 대한 답만 쓴다. 답변이 질문 밖 정보를 덧붙이면, 공고와 맞으면 감점 없음, 틀리면 오답 (A03 검수에서 정함).
- **일반 지식 추론**: 공고에 없는 일반 지식(예: Spring은 Java·Kotlin 기반)은 공고 근거와 질문을 잇는 데만 쓰고, 추론이라고 구분해 말해야 한다.
  추론을 공고 내용처럼 말하면 오답. 이런 문항은 `세부유형`에 "(추론 필요)"를 붙이고 `채점 메모`에 정답·부분·오답 조건을 적는다 (A05 검수에서 정함).

최신성(지표 1순위)은 A19·A20·T04의 답변 정확도를 따로 모아 보고한다.
보고 순서는 제안서 9-3의 우선순위를 따른다: 최신성 > 출처 정확도 > 답변 정확도 > 검색 적중률.

검색 적중률·근거 재현율·근거 표시 정확도·출처 정확도는 코드로, 답변 정확도·문서에 없는 질문 처리는 LLM으로 채점한다 (`src/run_eval.py`).
LLM 자동 채점과 사람 채점을 같은 기준으로 하고, 두 결과의 일치율을 함께 기록한다.

## 채점표 (실행 결과)

평가를 실행할 때마다 `eval/results/{실행일}_{전략}_k{top_k}_{모델}.csv`에 문항별로 기록하고,
`eval/results/summary.csv`에 실행마다 지표 한 줄을 쌓는다 (6단계 실험 로그). 사용 토큰과 비용은 `eval/usage_log.csv`.
공개 채점표에는 공고 원문 문장이 그대로 들어가는 `인용` 열을 빼고 `인용 검증` 수만 남긴다. 인용까지 포함한 전체 채점표는
`eval/results/raw/`에 저장하며 커밋하지 않는다 (원문 재배포 금지, `data/README.md` > 이용 조건).

| 열 | 내용 |
|---|---|
| `id` | 문항 ID |
| `설정` | 청킹 전략, top-k, 임베딩·LLM 모델, 프롬프트 버전 |
| `검색 결과` | top-k 청크의 `공고ID/항목키` 목록 |
| `검색 적중`, `근거 재현율` | 위 기준 |

## LLM 채점 vs 사람 채점

1차 기준선(전략 B, top-5, gpt-6-luna) 30문항을 사람이 채점해 LLM 채점(gpt-6-luna)과 비교했다.
채점표의 `사람 판정`·`메모` 열에 기록 (`eval/results/2026-10-02_B_k5_gpt-6-luna.csv`).

| 문항 | 사람 | LLM (채점 기준 v1) | 원인 |
|---|---|---|---|
| A04 | 부분 | 정답 | 필수 요소에 "스톡옵션 협의"가 없었음 (사람이 더 엄격) |
| A06 | 정답 | 부분 | 필수 요소의 "둘 다면 우대"는 필수가 아니라고 판단 |
| A08 | 정답 | 부분 | 필수 요소의 "첫 번째 개발자"는 핵심이 아니라고 판단 |

세 건 모두 LLM이 필수 요소를 잘못 적용한 것이 아니라, 필수 요소 자체가 사람 판단과 달랐다.
그래서 채점 프롬프트·채점 모델은 그대로 두고 평가셋의 필수 요소를 고쳤다.

사람 메모에서 채점 코드 문제도 하나 찾았다. A10은 챗봇이 채용절차를 찾지 못해 "확인되지 않습니다"라고 답하고 공고 개요를 근거로
표시했는데, 근거 표시 판정이 "정답"이었다. 코드가 공고ID만 비교했기 때문이다.

### 채점 기준 변경 기록

같은 답변(1차 기준선)을 바뀐 기준으로 다시 채점해(`run_eval.py --regrade`) 기준 변경 효과만 비교했다.

| 변경 | 전 → 후 (전략 B) | 이유 |
|---|---|---|
| 필수 요소 수정: A04 "스톡옵션 협의 가능" 추가, A06 "둘 다면 우대"·A08 "첫 번째 개발자" 삭제 (채점 메모로 이동) | 사람 일치율 90% (27/30) → **100% (30/30)**, 답변 정확도 64% → 66% | 사람 채점 결과에 맞춤 |
| 근거 표시 판정: 공고ID만 비교 → 공고ID+항목 비교 (공고는 맞고 항목이 다르면 부분) | 근거 표시 정확도 84% → **74%** (전략 A 82% → 74%) | A10처럼 틀린 답에 "근거 표시 정답"이 붙어 지표가 부풀려짐 |
| 정답지 수정 (v4, 2026-10-07): A03 필수 요소에서 시스템 프로그래밍 제외, A04에서 스톡옵션 제외, A09 필수 요소를 원문 표현으로 정정, A14 "섞이면 안 되는 내용"을 경력 공고ID로 구체화 | 답변 정확도 전략 B 66% → **72%** (전략 A 64% → 70%). 단계별 표는 아래 | 강사님 피드백(정답지는 질문만 보고 고친다). 질문이 요구하지 않는 요소, 원문에 없는 합성 표현, 확인할 수 없는 범주를 정정 |

주의: 필수 요소를 같은 30문항의 사람 판단에 맞춰 고쳤으므로 100%는 이 데이터에 맞춘 값이다.
다음 실행(새 답변)에서 사람 채점을 일부 다시 해 일치율이 유지되는지 확인한다.

### 정답지 수정(v4) 재채점 결과 (2026-10-07)

강사님 피드백에 따라 정답지를 질문만 보고 고치고(`eval/eval_set.csv`, 수정 전은 `eval/eval_set_v2.csv`), 기준선부터 7단계 이전 실험까지 원본 답변 15개를 처음 버전부터 모두 다시 채점했다(`run_eval.py --regrade`, 결과는 `_grade-v4.csv`, 기존 `_grade-v2.csv`·원본은 그대로). 채점 프롬프트와 채점 코드는 바꾸지 않았다.
고친 정답지는 A03, A04, A09, A14뿐이다. 정답지를 고치지 않은 문항의 판정도 재채점 LLM의 변동으로 바뀌어서, 변화를 "수정한 4문항의 몫"과 "그 외(노이즈)"로 나눠 적었다.
